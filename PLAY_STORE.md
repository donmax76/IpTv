# Публикация в Google Play (Play Market)

Приложение собирается в двух вариантах из одного кода (Round 376):

| Вариант | Что внутри | Формат | Обновления |
|---------|-----------|--------|------------|
| **github** | встроенный авто-апдейтер + `REQUEST_INSTALL_PACKAGES` | APK | скачивает APK сам |
| **play**   | БЕЗ апдейтера и без разрешения на установку APK | AAB (`.aab`) | через магазин Play |

Google Play **запрещает** приложениям обновлять себя самим — поэтому в
play-варианте авто-апдейтер отключён. Обновления пользователи получают
автоматически через магазин.

---

## Что нужно сделать ОДИН РАЗ

### 1. Аккаунт разработчика
- Зарегистрируйся: https://play.google.com/console (разовая оплата **$25**).

### 2. Создать ключ загрузки (upload key)
Google хранит основной ключ подписи (Play App Signing), а ты
подписываешь загрузки «ключом загрузки». Создай его:

```bash
keytool -genkeypair -v -keystore upload-key.jks \
  -keyalg RSA -keysize 2048 -validity 9125 \
  -alias upload -storepass ВАШ_ПАРОЛЬ -keypass ВАШ_ПАРОЛЬ \
  -dname "CN=TVViewer, O=TVViewer, C=RU"
```

⚠️ Файл `upload-key.jks` и пароли **НЕ клади в git**. Храни отдельно.

## Как собрать `.aab` для загрузки

### Вариант A — автоматически в CI (Round 379)

CI (`.github/workflows/build.yml`) собирает `.aab` **сам на каждый пуш**,
но только если в репозитории заданы секреты с ключом загрузки. Готовый
файл выкладывается как artifact `TVViewer-play-aab` в разделе Actions →
конкретный запуск → Artifacts. Скачай его оттуда и загрузи в Play Console.

Один раз добавь секреты: **Settings → Secrets and variables → Actions →
New repository secret**:

| Секрет | Значение |
|--------|----------|
| `UPLOAD_KEYSTORE_BASE64` | сам файл ключа в base64 (см. команду ниже) |
| `UPLOAD_KEYSTORE_PASSWORD` | пароль хранилища |
| `UPLOAD_KEY_ALIAS` | `upload` |
| `UPLOAD_KEY_PASSWORD` | пароль ключа |

Получить base64 из `upload-key.jks`:

```bash
base64 -w0 upload-key.jks         # Linux
base64 -i upload-key.jks          # macOS
```

Скопируй вывод целиком в значение секрета `UPLOAD_KEYSTORE_BASE64`.

Пока `UPLOAD_KEYSTORE_BASE64` не задан — шаг сборки `.aab` просто
пропускается (в логе появится notice), а обычная APK-сборка идёт как
раньше.

### Вариант B — локально

Нужен установленный Android SDK:

```bash
UPLOAD_KEYSTORE_FILE=/полный/путь/upload-key.jks \
UPLOAD_KEYSTORE_PASSWORD=ВАШ_ПАРОЛЬ \
UPLOAD_KEY_ALIAS=upload \
UPLOAD_KEY_PASSWORD=ВАШ_ПАРОЛЬ \
./gradlew bundlePlayRelease
```

Готовый файл:
`app/build/outputs/bundle/playRelease/app-play-release.aab`

(Если переменные окружения не заданы — `.aab` подпишется debug-ключом
и Play его **не примет**. Ключ загрузки обязателен.)

## Загрузка в Play Console

1. **Создай приложение** в Play Console → название, язык, тип «Приложение», бесплатное.
2. **Play App Signing** — оставь включённым (по умолчанию). При первой
   загрузке `.aab` Google сгенерирует ключ подписи и запомнит твой
   ключ загрузки.
3. **Загрузи `.aab`** в раздел «Тестирование → Внутреннее тестирование»
   (сначала лучше туда, потом «Продакшн»).
4. Заполни обязательное:
   - **Описание** приложения + короткое описание.
   - **Скриншоты** (минимум 2 для телефона; для Android TV — свои).
   - **Значок** 512×512, **Feature graphic** 1024×500.
   - **Возрастной рейтинг** (анкета).
   - **Форма «Безопасность данных»** — укажи, что приложение отправляет
     отчёты о сбоях (у нас авто-отправка крашей на GitHub/ntfy).
   - **Политика конфиденциальности** — нужна ссылка на страницу
     (можно короткую на GitHub Pages).
   - **Целевая аудитория**, страны распространения.

## Важно про контент (IPTV)

Google строго проверяет IPTV-приложения. Наше — это **плеер**:
плейлисты добавляет сам пользователь, встроенные подборки (iptv-org) —
публичные и легальные. Обычно проходит. Но:

- НЕ включай в поставку плейлисты с пиратским/платным контентом.
- В описании честно указывай, что это плеер, а контент пользователь
  добавляет сам.

## После публикации

- Новые версии: подними `versionCode` (в CI это номер сборки), собери
  новый `.aab`, загрузи в Play Console → выкати обновление.
- github-версия (APK на GitHub) продолжает жить параллельно со своим
  авто-апдейтером — трогать её не нужно.
